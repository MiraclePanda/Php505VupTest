# 差分の分類案（承認待ち）

旧環境（PHP 5.0.5）との差分と、その分類案。**承認されたものだけ** `docs/known-differences.md` に転記する。

- 比較の基準: **推定**。ゴールデン（旧環境の実測）は未記録のため、旧環境の php.ini とコードから推定した期待値
  （`tests/characterization/expectations.tsv`）と、PHP 5.0 と 8.5 の仕様の違いから判断した。
  旧環境でゴールデンを記録したら、この表を実測の差分で確かめ直すこと。
- 分類: **回帰**（直す）/ **仕様変更候補**（承認が要る）/ **環境差**（エラー文言など、承認が要る）

## 特性テストで見える差分

| # | ケース | 差分（旧 → 新） | 原因 | 分類案 | 推奨 |
|---|---|---|---|---|---|
| D1 | 全ケース | `Content-Type: text/html` → `Content-Type: text/html; charset=EUC-JP` | R10。PHP 8.5 は既定で charset=UTF-8 を付けるため、EUC-JP を明示した | 仕様変更候補 | 承認（charset なしに戻すと、ブラウザの自動判定に頼ることになる） |
| D2 | 18_update_invalid | 入力エラー時の再表示 `O''Reilly 本` → `O'Reilly 本` | R05。旧は magic_quotes_sybase で `'` が `''` になった値をそのまま再表示していた（旧のバグ） | 仕様変更候補 | 承認（旧の再現はしない） |
| D3 | 24_search_byte_boundary | 「酬」の検索で 1 件（表計算 ソフト 活用術）→ 0 件 | R12。旧の SQLite 2 の LIKE はバイト単位で、EUC-JP の文字境界をまたいで誤ヒットしていた（旧のバグ） | 仕様変更候補 | 承認 |
| D4 | 13 / 17 など DB エラー経路（テストなし） | `SQLエラー: [SQLite]...` → `SQLエラー: SQLSTATE[HY000]: ...` | R09。PDO_ODBC のエラー文言 | 環境差 | 承認 |

## テストにない入力での差分（コードの読み合わせで判明）

| # | 入力 | 旧 | 新 | 原因 | 分類案 |
|---|---|---|---|---|---|
| D5 | パスワードに `'` を含むユーザーのログイン | `md5("a''b")`（エスケープ後）で照合 | `md5("a'b")` で照合 | R05 | **要判断**: 既存ハッシュが旧画面経由で作られていれば、そのユーザーはログインできなくなる。本番に `'` を含むパスワードがありうるか確認が必要 |
| D6 | 商品名の長さ判定（`'` を含む名前） | エスケープ後のバイト数で判定（`'` 1 つにつき 1 バイト多く数えた） | 生の値のバイト数 | R05 | 仕様変更候補（旧のバグ） |
| D7 | `?error=...`（ログイン）、`?errors[]=...`（編集） | 外から渡した文字列が画面に出た（register_globals） | 出ない | R03 | 仕様変更候補（脆弱性の解消） |
| D8 | `category=2abc` など数値で始まる不正値 | SQL エラー（`= 2abc` を連結） | 0 件 | R09 | 仕様変更候補 |
| D9 | `category=1 OR 1=1` など SQL を含む値 | SQL インジェクション（全件） | 0 件 | R09 | 仕様変更候補（脆弱性の解消） |
| D10 | `'abc'` のように `'` で囲まれた検索語 | そのまま検索 | そのまま検索（PDO を選んだため差分なし。`odbc_execute` ならファイル読み込みになる） | R09 | 差分なし（記録のみ） |
| D11 | EUC-JP として不正なバイト列（Shift_JIS や UTF-8 で送られた検索語・商品名） | そのまま表示・生のバイト列で保存・バイト単位で検索 | 検索語の表示は `?`（mb_convert_kana が先に置換）。**保存すると DB 側で `?` に置き換わり、データが変わる**。検索も `?` に置換した語で行う | R10 / R12 | **要判断**（データが変わる）。案: 不正なバイト列を含む更新は入力エラーにする |
| D12 | 配列で渡されたパラメータ（`?keyword[]=x`、`name[]=x` など） | 関数ごとにまちまち（`"Array"` として保存、全件一覧、SQL エラー） | 未指定として扱う（R15）。検索は全件、ログインは失敗、更新は「商品名を入力してください」 | R15 | 仕様変更候補（正常な操作では起きない）。**R15 の前は TypeError で Fatal だった（回帰。意味レビューで判明し修正）** |
| D13 | `updated_at` の値 | OS のタイムゾーン（コンテナでは UTC と推定） | `date.timezone = Asia/Tokyo` | R13 | **要確認**: 本番の旧サーバのタイムゾーン。画面には出ない |

## DB

| # | 項目 | 旧 | 新 | 分類案 |
|---|---|---|---|---|
| D14 | DB の文字コード | EUC-JP のバイト列（SQLite 2） | UTF-8（SQLite 3）。アプリとの境界で変換 | **要判断**（推奨: UTF-8）。本番 Symfoware でも同じ判断が要る |
| D15 | 数値列に文字列のパラメータ | SQL に数値リテラルとして連結 | 文字列としてバインドし、DB が数値に変換（SQLite で `"0012"` → 12 を確認） | Symfoware での暗黙変換の規則は未確認 |
| D16 | 文字列の長さ（`VARCHAR(50)` など） | EUC-JP で全角 1 文字 2 バイト | UTF-8 で全角 1 文字 3 バイト | **要確認**: 本番 Symfoware の長さがバイト単位なら、全角 34 文字以上の商品名・カテゴリ名・利用者名で更新とデータ移行が失敗する。文字単位か、列の拡張が要るか |
