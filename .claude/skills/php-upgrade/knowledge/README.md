# 移行ノウハウの蓄積

移行を繰り返すたびに精度を上げるための記録。`php-upgrade` スキルは開始時にここを読み、`upgrade-retro` スキルが終了時に更新する。

| ファイル | 内容 | 更新するとき |
|---|---|---|
| `lessons.md` | 横断的な学び（手順、道具、判断の勘所） | 振り返りで毎回 |
| `../rules/R*.md` の「落とし穴」 | ルール固有の学び、detect パターンの改善 | 見逃し・誤修正があったとき |
| `metrics.md` | 実施ごとの指標（検出率、修正率、誤修正、介入回数） | 振り返りで毎回 |
| `runs/<実施 ID>.md` | 実施ごとの振り返りの全文 | 振り返りで毎回 |

## 改善のループ

1. 移行を実施する（`php-upgrade`）。レポートの「つまずき」に気づいたことを書いておく。
2. 振り返り（`upgrade-retro`）: 解答キー（実案件では本番障害・テスト結果・人のレビュー指摘）と突き合わせ、
   - **見逃し**: なぜ見つけられなかったか → detect パターン追加、棚卸し手順の追加、新ルール
   - **誤修正**: なぜ振る舞いを変えたか → ルールの「落とし穴」、レビュー観点の追加
   - **手戻り**: どこで時間を使ったか → 道具（scripts/upgrade）の改善
3. 指標を `metrics.md` に記録し、前回と比べる。改善が効いたかは同じ条件の再実行で確かめる。

## 書き方
- 学びは「状況 → 何が起きたか → 次からどうするか → どこに反映したか」で書く。
- 同じ学びを 2 か所に書かない。ルール固有なら rules/、横断的なら lessons.md。
- 実案件に持ち出せない情報（顧客名、本番データ）は書かない。
