## 何が起きるか
`short_open_tag = Off`（PHP 8 系の推奨値）では `<?` 以降が PHP として解釈されず、**ソースコードがそのままブラウザに出る**。
DB 接続情報などが漏れる重大事故になる。

## 直し方
- `<?` → `<?php`。直後が改行でも空白でもよいが、`<?php` の後には空白か改行が必要（`<?phpif` は不可）。
- `<?=` は PHP 5.4 以降 short_open_tag と無関係に常に有効なので、そのままでよい。
- `<?xml` を出力している箇所は文字列なので対象外（`echo '<?xml ...'` に書き換えていればそれも対象外）。

## 落とし穴
- **`php -l` は検出しない。** short_open_tag=Off では `<? ... ?>` はただの HTML とみなされ、構文エラーにならない。
  `scripts/upgrade/lint.sh` が OK でも安心しないこと。
- `.inc` / `.tpl` など拡張子が `.php` 以外のテンプレートにも多い。
- ファイル末尾の `?>` の後の改行は PHP が 1 つだけ食う。置換で改行を増やすと出力が変わる。

## 確認
`python3 scripts/upgrade/scan.py newapp/app --rule R01` が 0 件。

## 学び（実施記録）
- 2026-10-22-01: 移行前のアプリを新環境で動かすと全画面でソースが露出し、`php -l` は全ファイル OK だった（短縮タグ部分が HTML 扱い）。`verify.sh` の「ソースが出力されている疑い」と R01 の scan で検出した。
