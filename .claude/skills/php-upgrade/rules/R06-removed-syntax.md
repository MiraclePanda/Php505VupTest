## 何が起きるか
| 構文 | 削除 | PHP 8.5 での症状 |
|---|---|---|
| 実行時参照渡し `f(&$x)` | 5.4 | Parse error |
| `$o =& new C()` | 7.0 | Parse error |
| 波括弧の文字列オフセット `$s{0}` | 8.0 | Parse error |
| `(integer)` `(boolean)` `(double)` `(binary)` | 8.5 で非推奨 | Deprecated（`(real)` は 8.0 で削除、Parse error） |
| `(unset)` キャスト | 8.0 | Parse error |
| 括弧のない入れ子の三項演算子 `a ? b : c ? d : e` | 8.0 | Fatal（コンパイルエラー）。旧は**左結合**で `(a ? b : c) ? d : e` と評価していた |
| 文字列中の `"${var}"` | 8.2 で非推奨 | Deprecated。`"{$var}"` に |

## 直し方
- 実行時参照渡し: **関数定義の引数に `&` を付け**、呼び出し側の `&` を消す。定義側に付けないと、呼び出し側で消しただけでは変更が反映されなくなり、**エラーにならずに結果が変わる**。
  - 組み込み関数に `&$x` を渡している場合は、その関数がもともと参照で受けるかを確認して `&` を消すだけでよい。
- `=& new` → `= new`（PHP 5 以降オブジェクトはハンドル渡し）。
- `$s{0}` → `$s[0]`。ただし範囲外の添字は PHP 8 で Warning（旧環境は Notice で抑止されていた）。長さが保証されないなら `substr($s, 0, 1)` にすると旧の「空文字を返す」挙動のまま Warning も出ない。
- `(integer)` → `(int)`、`(boolean)` → `(bool)`、`(double)` `(real)` → `(float)`、`(binary)` → `(string)`、`(unset)$x` → `null`。

## 落とし穴
- detect の 1 つ目（`(&$x` / `, &$x`）は関数定義の `function f(&$x)` も拾う。定義は正しい書き方なので対象外。
- 参照渡しで受けていた関数を、同じ値で別の場所からも呼んでいないか（定義に `&` を付けると全呼び出しが参照渡しになる）確認する。
  参照で受けると困る呼び出し（リテラルを渡しているなど）があれば Fatal になる。

## 学び（実施記録）
- 2026-10-22-01: `$s{0}` は `$s[0]` ではなく `substr($s, 0, 2)` にした（短い文字列で旧と同じく空文字・警告なし）。解答キーの案（`$code[0]`）より旧の挙動に忠実。
- 2026-10-22-03（app2）: `$row["important"] ? "重要" : is_new(...) ? "新着" : "通常"` は旧の左結合では重要なお知らせが「新着」になる（旧のバグ）。自然に読んで右結合の括弧を付けると表示が変わる。**旧の評価順（左結合）を括弧で明示**して結果を保ち、直すなら改善として人に上げる。
